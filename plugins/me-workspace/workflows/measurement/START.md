# Feasible measurement starter pack

This pack helps you complete one M&E job with free instructions and fictional attachments. Your Claude account has its own access and usage limits. Checked in Claude Code. Anthropic's help page says Free and paid plans can use uploaded skills once code execution is turned on; we checked browser upload on a paid plan only. No API key or site signup is needed.

## Inputs and start

Supply `feasible-measurement.md` or your equivalent readable files. examples/normal and examples/difficult are separate fictional cases; never combine them. Browser users upload files; Code users give explicit file paths or a scoped folder. If extraction fails, provide a readable text export. This pack promises Markdown output, not Word, PDF or spreadsheet rendering.

Enable these workspace skills: measurement-feasibility, indicator-reference-sheets, me-plan-draft. Also enable the review skill(s) indicator-quality and me-plan-review from me-review. In Code load both plugins and use `/me-workspace:<skill>` and `/me-review:<review>`. In a browser upload individual skill packages and name the skill. Copy/paste fallback: paste each relevant SKILL.md in sequence with the files or text it needs; browser behavior still needs separate verification.

Starter: Complete feasible measurement with my supplied documents. Use me-review:indicator-quality to write indicator-review.md. Use measurement-feasibility for burden.md, indicator-reference-sheets for reference-sheets.md, and me-plan-draft for me-plan.md. Use me-review:me-plan-review for coherence.md, compare every indicator ID/definition/denominator/source/frequency/role/use across artifacts, flag each inconsistency in coherence.md, then correct it in the affected file and note the change in decisions.md. Record suggested indicator revisions and unresolved decisions in decisions.md. Preserve required evidence and reporting obligations when reducing burden. Sum time by role and actual collection month, separating one-time and recurring tasks. Do not assume extra capacity or equate sessions with active weeks. When calendar counts are absent use the supplied weekly/per-event rate and a formula for total burden; any optional scenario is not a source-supported total. All-eligible confirmed-positive shares do not classify unknown individuals as negative: show missing statuses and respondent-only rates separately and keep interpretation consistent across artifacts. Return the final artifacts in editable Markdown. Separate facts, assumptions and proposed choices. Make unresolved decisions explicit.

## Save and resume

Number decisions with the stage prefix (MEAS-D1, MEAS-D2) so each ID means one decision across all files. Save intermediate outputs as you go. If interrupted, use handover-template.md to state the input files/source IDs, completed files, decisions/assumptions, remaining steps and exact restart instruction. In a fresh session provide the original input, completed artifacts and handover. Re-validate inherited facts and status claims against the original sources before copying them forward. A handover is a navigation aid, not authority for approval, consent or measurement definitions. Use three evidence states: explicitly confirmed, explicitly contradicted, or unconfirmed. No supporting record means unconfirmed; it cannot justify keeping a negative status claim. If a resumed claim has no supporting record, mark it unknown rather than keeping it. Distinguish approval status of pre-existing program items from recommendations created in this draft (proposed). Do not rely on earlier chat memory or undocumented author corrections.

Expected files: indicator-review.md, burden.md, reference-sheets.md, me-plan.md, coherence.md, decisions.md. Check that you can open each file, follow source IDs back to inputs, distinguish proposals from commitments, and see the next decision. Human usability validation remains pending.
