# Reporting to action starter pack

This pack helps you complete one M&E job with free instructions and fictional attachments. Your Claude account has its own access and usage limits. Checked in Claude Code. Anthropic's help page says Free and paid plans can use uploaded skills once code execution is turned on; we checked browser upload on a paid plan only. No API key or site signup is needed.

## Inputs and start

Supply `reporting-to-action.md` or your equivalent readable files. examples/normal and examples/difficult are separate fictional cases; never combine them. For reporting, examples/single-period tests the no-trend boundary. Browser users upload files; Code users give explicit file paths or a scoped folder. If extraction fails, provide a readable text export. This pack promises Markdown output, not Word, PDF or spreadsheet rendering.

Enable these workspace skills: progress-evidence, findings-to-actions. Also enable the review skill(s) progress-report-review from me-review. In Code load both plugins and use `/me-workspace:<skill>` and `/me-review:<review>`. In a browser upload individual skill packages and name the skill. Copy/paste fallback: paste each relevant SKILL.md in sequence with the files or text it needs; browser behavior still needs separate verification.

Starter: Complete reporting to action with my supplied documents. Use progress-evidence to write evidence.md, including coverage, arithmetic and comparison eligibility. Save the supplied draft report unchanged as report-draft.md; if none is supplied, draft one from evidence.md and label it a draft. Use me-review:progress-report-review on that draft and the input to write review.md. Revise into report-revised.md, then use findings-to-actions on supported findings to write actions.md. Record material revisions and unresolved decisions in change-record.md. Reconcile all numbers and keep period/cumulative, count/event, denominator and comparison limits consistent across evidence, report and actions. A single-period case permits no cross-period trends. Qualitative findings are not representative prevalence or causal proof. Suggested owners/dates remain proposed unless explicitly committed in the source. Return the final artifacts in editable Markdown. Separate facts, assumptions and proposed choices. Make unresolved decisions explicit.

## Save and resume

Number decisions with the stage prefix (REP-D1, REP-D2) so each ID means one decision across all files. Save intermediate outputs as you go. If interrupted, use handover-template.md to state the input files/source IDs, completed files, decisions/assumptions, remaining steps and exact restart instruction. In a fresh session provide the original input, completed artifacts and handover. Re-validate inherited facts and status claims against the original sources before copying them forward. A handover is a navigation aid, not authority for approval, consent or measurement definitions. Use three evidence states: explicitly confirmed, explicitly contradicted, or unconfirmed. No supporting record means unconfirmed; it cannot justify keeping a negative status claim. If a resumed claim has no supporting record, mark it unknown rather than keeping it. Distinguish approval status of pre-existing program items from recommendations created in this draft (proposed). Do not rely on earlier chat memory or undocumented author corrections.

Expected files: evidence.md, report-draft.md, review.md, report-revised.md, actions.md, change-record.md. Check that you can open each file, follow source IDs back to inputs, distinguish proposals from commitments, and see the next decision. Human usability validation remains pending.
